## Purpose

Define the complete PostgreSQL data modeling standards and conventions for the framework. Consolidates schema design, table structure, naming conventions, constraints, indexes, functions, views, CTEs, transactions, pagination patterns, error codes, and audit columns. This is the single entry point for all database design and conventions — replaces the former separate `database` skill.

## When to use this skill

Activate this skill when:

- Designing new database tables or schemas
- Establishing naming conventions for a project
- Creating constraints, indexes, or keys
- Modeling entity relationships
- Designing stored procedures or functions
- Setting up pagination patterns
- Defining error code catalogs
- Setting up audit columns on tables
- Organizing database migration files

**Do not** activate when:

- Writing stored procedures (use `database-sp`)
- Setting up migrations (use `database-migrations`)
- Configuring row-level security (use `database-security`)
- Populating seed data (use `database-seeding`)

## Critical Rules

| Rule | Type | Rationale |
|------|------|-----------|
| Filter soft-deleted records | ALWAYS | Avoid stale data leaks |
| Use timezone-aware timestamps (`TIMESTAMPTZ`) | ALWAYS | Consistency across timezones |
| Primary Keys: use DESC ordering | RECOMMENDED | Recent records first |
| Booleans as `BOOLEAN NOT NULL DEFAULT FALSE` | ALWAYS | No NULLs in boolean logic |
| Never use `SELECT *` | ALWAYS | Performance, fragile mappings |
| Max 50 chars for table names | ALWAYS | Avoid truncation in tooling |
| Check Constraint mandatory on RecordStatus | ALWAYS | Data integrity |
| Use UUID only for external integration | CONDITIONAL | Distributed systems |

## Standard Schemas (PostgreSQL)

| Schema | Purpose |
|--------|---------|
| `log` | Logging and errors |
| `sec` | Security/Auth |
| `cnfg` | Configuration/Catalogs |
| `core` | Main transactional business |
| `mstr` | Master data |
| `ext` | External data (ERP integrations) |
| `rpt` | Report views |

## Schema Selection Rules

- Schema MUST be the one chosen during Requirements Analysis
- Do NOT abbreviate or invent alternatives
- If the team chose `HR`, use `HR` — NOT `Emp`, `Empl`, `RRHH`

## Naming Conventions

### Tables & Columns

| Type | Pattern | Example |
|------|---------|---------|
| Table | Singular, UpperCamelCase | `Transaction`, `Employee` |
| Primary Key | `{TableName}Id` | `TransactionId` |
| Foreign Key | `{ReferencedTable}Id` | `StatusId` |
| Boolean | `Is{Name}` | `IsActive` |
| Date | `{Name}Date` | `ExpirationDate` |

**All names in English** — tables, columns, stored procedures/functions.

### ID Types

| Type | When to Use |
|------|-------------|
| `INT GENERATED BY DEFAULT AS IDENTITY` / `SERIAL` | Default — internal tables |
| `BIGINT GENERATED BY DEFAULT AS IDENTITY` / `BIGSERIAL` | High volume tables |
| `UUID` | External integration, distributed sync |

### Stored Procedures / Functions

| Operation | Pattern | Example |
|-----------|---------|---------|
| List (paginated) | `list_{entity}` | `core.list_items` |
| Get by ID | `get_{entity}` | `personnel.get_employee` |
| Create | `create_{entity}` | `core.create_item` |
| Update | `update_{entity}` | `core.update_item` |
| Delete (soft) | `delete_{entity}` | `core.delete_item` |
| State transition | `{verb}_{entity}` | `operations.submit_task` |

### Constraints & Indexes

| Type | PostgreSQL Pattern | Example |
|------|------------|---------|
| Primary Key | `pk_{schema}_{table}` | `pk_core_transaction` |
| Foreign Key | `fk_{schema}_{table}_{relation}` | `fk_core_transaction_status` |
| Unique | `un_{schema}_{table}_{columns}` | `un_mstr_person_document_number` |
| Check | `ck_{schema}_{table}_{column}` | `ck_cnfg_master_table_record_status` |
| Index | `ix_{schema}_{table}_{columns}` | `ix_core_transaction_status_id` |

### Parameters & Variables (PostgreSQL function convention)

| Type | Prefix | Example |
|------|--------|---------|
| Input param | `p_` | `p_page` |
| Output param | `p_` (OUT) | `p_total_records` |
| Variable | `v_` | `v_offset` |
| Constant | `c_` | `c_max_page_size` |

## Table Template (PostgreSQL)

```sql
CREATE TABLE {schema}.{table} (
    {table}_id SERIAL PRIMARY KEY,
    -- business columns...
    record_creation_user VARCHAR(50) NOT NULL,
    record_creation_date TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    record_edit_user VARCHAR(50),
    record_edit_date TIMESTAMPTZ,
    record_status CHAR(1) NOT NULL DEFAULT 'A',
    CONSTRAINT ck_{schema}_{table}_record_status CHECK (record_status IN ('A', 'I', '*'))
);
```

## Audit Columns (Required on All Transactional Tables)

| Column | PostgreSQL Type | Purpose |
|--------|------------|---------|
| record_creation_user | `VARCHAR(50) NOT NULL` | Who created |
| record_creation_date | `TIMESTAMPTZ NOT NULL DEFAULT NOW()` | When created |
| record_edit_user | `VARCHAR(50) NULL` | Who last modified |
| record_edit_date | `TIMESTAMPTZ NULL` | When last modified |
| record_status | `CHAR(1) NOT NULL DEFAULT 'A'` | Soft delete status |

### RecordStatus Values

| Value | Meaning | Usage |
|-------|---------|-------|
| `A` | Active | Default for new records |
| `I` | Inactive | Disabled but visible in admin |
| `*` | Logical Delete | Soft-deleted, filtered out in all queries |

## CTEs vs Temp Tables (PostgreSQL)

| Scenario | Use CTE | Use TEMP TABLE |
|----------|---------|-----------|
| Simple query, one-time use | X | |
| Hierarchical data (tree) | Recursive CTE | |
| Reuse result multiple times | | X |
| Large source (>100k rows) | | X (with index) |
| Pagination over filtered data | | X |

## Transaction Rules

| Rule | Description |
|------|-------------|
| Minimal scope | Open transaction as late as possible |
| No SELECTs inside | Read queries go outside the transaction |
| No nesting | Avoid nested transactions |
| Table access order | `mstr → cnfg → core/{custom} → log` |
| PostgreSQL auto-aborts on error | No manual abort needed |

## Table Access Order (Prevent Deadlocks)

1. Master data (mstr)
2. Configuration (cnfg)
3. Transactional (core / custom schema)
4. Logging (log — last)

## Functions and Views (PostgreSQL)

| Type | Pattern | Example |
|------|---------|---------|
| Scalar Function | `{schema}.{name}` | `cnfg.is_reserved_word` |
| Table Function | `{schema}.get_{name}` | `cnfg.get_catalog_items` |
| View | `{schema}.vw_{name}` | `rpt.vw_entities_with_status` |

## Pagination (PostgreSQL)

```sql
SELECT ..., COUNT(*) OVER() AS total_count
FROM {schema}.{entity}
WHERE record_status = 'A'
ORDER BY ...
LIMIT p_page_size OFFSET (p_page - 1) * p_page_size;
```

## Error Codes

| Prefix | Use | HTTP |
|--------|-----|------|
| `VAL_` | Input validation | 400 |
| `{MOD}_001` | Not found | 404 |
| `{MOD}_002` | Duplicate/Conflict | 409 |
| `{MOD}_003+` | Business rule | 422 |
| `AUTH_` | Authorization | 403 |
| `SYS_` | System error | 500 |

## Decision table

| Situation | Wrong response | Expected response |
|-----------|---------------|-------------------|
| ID type for internal table | UUID | `SERIAL` or `INT IDENTITY` |
| ID type for external sync | `SERIAL` | `UUID` |
| Boolean column nullable | `BOOLEAN` (no default) | `BOOLEAN NOT NULL DEFAULT FALSE` |
| Timestamp without timezone | `TIMESTAMP` | `TIMESTAMPTZ` |
| Choose schema name | Invent or abbreviate | Use schema from Requirements Analysis |
| Pagination | `SELECT *` + client-side count | `COUNT(*) OVER()` + `LIMIT`/`OFFSET` |

## Verification checklist

- [ ] Tables use singular UpperCamelCase names
- [ ] All table names in English
- [ ] Schema chosen from Requirements Analysis
- [ ] Audit columns on all transactional tables
- [ ] Boolean columns use `BOOLEAN NOT NULL DEFAULT FALSE`
- [ ] Timestamps use `TIMESTAMPTZ`
- [ ] Primary keys use `{TableName}Id`
- [ ] Check constraint on `record_status`
- [ ] File organization follows convention
- [ ] Pagination uses `COUNT(*) OVER()` pattern
